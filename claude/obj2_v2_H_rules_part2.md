### T, tie-break the model's hole ranking with B1 exact

- Scope: BNM fit half only (development data). Inputs: H2b's files (h2b_predicted.npz, h2b_scores.npz, h2b_report.json), the fit-half truth files through H2b's read_labels, H2a's baselines. Nothing of the test half, H5, H6 or real_eval is loaded (np.load refused, as F0).
- Score: within each stack-repeat, hole tetrads are ordered by the model's score first; tetrads with the same model score are ordered by the B1 exact score. Tetrads equal on both stay tied. Nothing is fitted and there is no parameter, so no folds are needed.
- How it is computed: score_T = model score + r / (2 x 50), with r the rank of the B1 exact score among the stack-repeat's holes scaled to [0, 1) (0-based, ties share their mean rank, divided by the number of holes). Gate: every model score x 50 is a whole number (tolerance 1e-5, see the correction below), so the smallest gap between two model scores is 1/50 and the added term (below 1/100) never changes the model's own order. If the gate fails the tool stops and the table goes to Sara.
- Correction found in the sandbox before any T value (15 Nov, labelled): the tolerance was written as 1e-6. H2b stores the model score as float32, and float32(k/50) x 50 differs from k by up to 1.43e-6 (k = 36), so a 1e-6 gate would stop the tool on correct data. Tolerance set to 1e-5; the smallest stored gap between two model scores is 0.0199999, still twice the largest added term. The order gate (below) checks the result on every stack-repeat either way.
- Rule, the F0 shape: "T worth using" = YES when, for seed 1 and seed 2, against B1 stored and B1 exact, with H2b's H-R1 code (stack-first means, 2,000 resamples of the 44 windows, seed 31, floor 50 distinct stacks): (i) no group of either grouping FAILs, and (ii) recorded classes 21-50 and 51+ and records 21+ keep a mean of 0 or above. Otherwise NO. Sara decides either way.
- Reported beside it: the unchanged H2b rows; per group the stack-first mean of AUC(T) minus AUC(model) with its interval; the share of recorded-against-unrecorded hole pairs the model ties, per group (the room T has); the sparse set S of H3b pooled (kept recorded class 0-1 in 2019, or 1-10 kept records over 6 years).
- Code gates (tool names V0-V4): V0 inputs = the H3 freeze list, stage_h6_bnm_test_score.py 8b9a38dd, stage_f0_spread_check.py version 2 by content (its loader, H-R1 closure and np.load log are reused), H2b's report gates; V1 alignment as F0's A1, the whole-number gate, B1 exact never NaN at a hole; V2 with the added term set to 0 the H-R1 rows = h2b_report.json (1e-9, same verdicts); V3 the order of any two holes with different model scores is the same before and after and they never tie (every stack-repeat), AUC(T) = AUC(model) on every stack-repeat with no tied recorded / unrecorded pair, and with B1 exact replaced by a constant AUC(T) = AUC(model) exactly; V4 np.load log.
- What a YES means: development evidence only. The fit half was used for every earlier choice and the test-half labels were read once at H6. A test-half score of T is a labelled second look and needs Sara's yes after the fit-half result. T changes the order of cells in a map; it changes no AOO, interval or P in the P3 or P4 products.
- Known limit, stated now: against B1 exact, T can gain only on pairs the model ties, and there it copies B1 exact. So T can lift the model to about B1's level in the sparse groups, and above it only where the model's strict ordering already beats B1.

### S, level correction by recorded class and the model's own raw size

- Scope: real_val only (development data). Inputs: P4-1's p4_1_crossfit.npz (371f424a) and p4_1_report.json (5e980763). No truth file, nothing of real_eval or BNM.
- Size of a stack = the mean land-only AOO over the method's own maps, before any correction (from the maps only; no truth).
- Grouping "option 3": recorded class x size bin, with the recorded class as the parent group. G3's crossfit, evaluate and rule_pass are used unchanged, on G3's community folds, with G3's fallback (fewer than 30 fit stacks: the recorded class, then all).
- Size bins (Q1, read as yes): 3 bins per recorded class, cut at the terciles of the size. For the stacks of a check fold the cut points come from the other fold's stacks, so no number of the check fold enters its own grouping.
- Methods: seed 1, seed 2, pooled (the product line), and B3, B4, B5 beside them.
- Rule: "S worth a labelled reading of real_eval" = YES when, for pooled and for both seeds, out of fold: (i) G3's rule passes (ratio 0.8-1.25 and coverage 0.85-0.95 in every recorded class and records bin with 50 or more stacks); and (ii) the ratio at land-only true class 1 under option 3 minus the same ratio under P4-1's stored cross-fit has its interval below 0 (2,000 resamples of the 20 communities, numpy seed 31, the same draws for both). Otherwise NO. Sara decides either way.
- Reported beside it: rows by size bin; ratio and coverage at true class 1 and 2-5; median interval width by recorded class against P4-1's; mean G3 P(AOO <= 1) and P(AOO <= 5) from the corrected maps at true class 1, labelled "before recalibration"; the rank correlation of size and true land-only AOO within each recorded class; crossed intervals counted (rule E).
- Code gates: inputs = Sara's P4-1 run; with one size bin per class the tool's cross-fit = P4-1's stored mean, L, U for every method at option 1 (1e-9); the check fold's cut points unchanged when that fold's sizes are replaced by random values; each fold's corrected values unchanged when that fold's truth is shuffled; np.load log (only the one npz).
- Correction (my error, step 45): I wrote that S helps only if true AOO grows less than in proportion to the raw size within a class. That is one-sided. S changes nothing when truth is proportional to size within a class; when it is not, the scale differs by bin, and whether the true 1-cell ratio falls depends on which bins the truly 1-cell stacks sit in. The direction is not known in advance; (ii) measures it.
- What a YES means: a candidate only. real_eval has been read twice, so a reading with option 3 would be a labelled third reading with its fits md5-logged first, and any products would be a new labelled version. P4 stays as signed.

### B-1a, the habitat axis from the Land Cover Map

- Map: UKCEH LCM 2019 1 km percentage target, GB (md5 d66aac88; 21 bands, band k = class k, confirmed at P3c-2b). Window grid as step 10 and P3c (row from the south, column from the west, 2 km tetrads, the four 1 km cells of tetrad (r, c) of window (e, n) at eastings e + 2c, e + 2c + 1 and northings n + 2r, n + 2r + 1 km); a cell outside the raster counts 0.
- Composition of a tetrad: per class, the sum of its four cells' percentages, divided by the sum over all 21 classes. A tetrad whose 21 classes sum to 0 (open sea, outside the raster) has no composition.
- Fit set: the tetrads of the 44 fit-half windows that lie in L_w (P4-0's land mask, p4_windows.npz 928cf96c) and have a composition; each window-tetrad once.
- Axis: the first principal component of the 21-share vectors over the fit set (covariance, ddof 1; numpy eigh). Sign: the class with the largest absolute loading is given a positive loading. Only PC1 is used; PC2 and PC3 are reported, never tested.
- Map value: score = (composition - fit-set mean) . PC1; per window z-scored over its L_w tetrads that have a score (as channel 18 is z-scored with the map's own mean and sd); tetrads outside L_w or with no composition get 0 (the value channel 18 takes where there is no habitat).
- Control map for B-1b: the 44 windows in name order; window k takes the map of window (k + 22) mod 44 (another real map of the same smoothness, as stage D's other-community control).
- Gates: J0 inputs (map md5; p4_windows.npz and p4_0_report.json md5 = P4-0 and its gates PASS); J1 grid (land from the composition by the P3c rule = P4-0's LCM land in every window, 0 differences; 21 bands, uint8, EPSG 27700, 1 km pixels on whole km); J2 code (eigh = SVD to 1e-9; z mean 0 and sd 1 over the scored L_w tetrads of every window, 1e-9; compositions sum to 1, 1e-9; a plain loop on 3 windows = the vectorised composition); J3 np.load only on p4_windows.npz (no BNM record, label, test-half or real_eval file); J4 outputs written once into a new folder and read back equal.
- Reported, no rule: variance share of PC1-PC3; PC1 loadings by class; per window the scored and zero tetrads; the share of L_w tetrads with no composition.
- Limit stated now: one axis of land-cover composition at 2 km cannot hold every butterfly's habitat; B-1b measures whether it carries signal for the recorded species.

### B-1b, K2 on the fit-half holes (rule written 16 Nov, step 58, before any B-1b value; signed by Sara 16 Nov, M3)

- Inputs fixed: B-1a ran 16 Nov (step 54; b1a_habitat.npz fac95acf, b1a_report.json 71e2bedb); PC1 = pasture against arable (improved grassland +0.886, arable -0.424), 0.375 of the variance. Sara 16 Nov: M1 yes (both maps scored on the same holes), M2 yes (PC1 kept as signed; no second axis tested).
- Question: on the BNM fit half, do hidden recorded tetrads sit closer on the habitat axis to the species' kept records than hidden unrecorded tetrads do, and more so with the window's own map than with another window's map? Report only; nothing is fitted (no parameter, no folds); the model, its samples, h3_freeze.json, the P4 fits and every product stay as they are.
- Items: H2b's fit-half stack-repeats and hole tetrads (h2b_predicted.npz hole_ptr, hole_cell, dist_h, rcls, rbin, stack_id), labels by H2b's read_labels (hole recorded in 2019), windows from bnm_stacks.npz, kept records from the inputs (stage_g_baselines load_obs, visit1 | visit2, any of the 6 years).
- Far holes: dist_h >= 3 (H2a's Euclidean distance to the nearest kept record of any year; tolerance 1e-4 for float32; for whole-cell offsets Euclidean >= 3 equals the training K2's Chebyshev >= 3). Near holes are not scored.
- Maps: own arm z = b1a z of the stack-repeat's window; control arm z = b1a z of window (k + 22) mod 44 in name order (b1a control_index). A tetrad is scored in a map when b1a scored is True there (in L_w and with a composition).
- Common support (M1): in each stack-repeat, a far hole is kept when it is scored in both maps; the kept-record set is the kept-record tetrads (each tetrad once) scored in both maps. Both arms use the same holes and the same records, so they differ only in the map values. (Detail fixed now: step 54 proposed each arm's own scored records; the same records for both arms is chosen so that the map is the only difference.) A stack-repeat with no kept record left in the support is dropped from both arms.
- Score: s = -|z(hole) - mean z over the kept-record set|, i.e. minus the model's channel 20 (stage E hab_dist) built from this map. AUC per stack-repeat over its kept far holes, recorded against unrecorded, ties half (H2b's item_aucs); rankable when both are present. d = AUC(own) - AUC(control) per rankable stack-repeat.
- Groups as H-R1: kept recorded class at 2019 (0, 1, 2-5, 6-10, 11-20, 21-50, 51+) and kept records over 6 years (1-3, 4-6, 7-10, 11-20, 21+); sparse set S of H3b = recorded class 0-1 or 1-10 kept records. Stack-first means and 95% intervals from 2,000 resamples of the 44 windows, seed 31 (H2b's hr1_core / hr1_rows, as T); floor 50 distinct stacks.
- Rule (the B-1 part of the signed go rule, 14 Nov): B-1 PASS when, in S pooled, the stack-first mean of d has its 95% interval above 0 (lower end > 0) with 50 or more distinct stacks. Otherwise B-1 FAIL: B stops (B-2 and the GPU step are not run) and the paper states the habitat limit with the B-0 and B-1 numbers. Sara decides either way.
- Reported, no rule: per group and in S, the mean of AUC(own) - 0.5, AUC(control) - 0.5 and d with intervals; rankable stack-repeats and distinct stacks; far holes kept and dropped by the support rule, and stack-repeats dropped for no kept record in the support, per group; stack-repeats where the support removed any kept record.
- real_val reference (report only; development data; inputs only, no truth file): the 8,174 habitat-shown stacks of stage_d_frozen_val.npz (blank 0; md5 = P4-1's frozen md5, as B-0). Holes by H1's rule from the input files: 5 repeats, (3n + 5) // 10 of the n tetrads surveyed at the target year (none when n < 2), drawn from effort only with seed key 31401 and (frozen row, repeat); records and effort removed in the holes in all 6 years; label = the input record at the target year in the hole; stack-repeats with no hole or no kept record left out and counted. Own map = the stored noisy habitat (habitat_noisy[stack_hab], K2 0.80 by construction); control = stage D's partner rule (a stack of the next community in seed order, same position modulo its size). Every cell is scored in simulation, so the support rule drops nothing (printed). Same score, far rule, groups and S; stack-first means with 2,000 resamples of the 20 communities, seed 31. It reads the BNM numbers against a habitat of training strength.
- Gates (tool names W0-W6; if one fails, nothing past it is printed and nothing is written): W0 inputs: b1a_habitat.npz and b1a_report.json md5 = step 54 and its gates PASS; h3_freeze.json = signed and its md5 list = the files now; h2b_report.json gates PASS; stage_f0_spread_check.py version 2 by content; stage_d_frozen_val.npz md5 = P4-1's record; every real_val input md5 = its manifest. W1 alignment: b1a window names = the 44 fit-half windows of bnm_stacks; dist recomputed from the kept records = h2b dist_h at every hole (1e-5); labels = H2b's read_labels; kept-record tetrads off L_w at most 0.5% (P3c: 3 of 20,738), the count with the map flipped north-south printed beside. W2 code: AUC by a plain loop on 3 windows = vectorised (1e-12); a positive scale and shift of a window's map leaves every AUC unchanged (1e-12); control map set to the own map gives d = 0 on every stack-repeat; a constant map gives AUC 0.5 at every rankable stack-repeat; on real_val, the tool's own-arm scores = minus stage_g_baselines hab_dist of the kept records and the stored habitat (1e-9). W3 support: both arms use identical holes and kept records on every stack-repeat; no kept hole is unscored in either map.
